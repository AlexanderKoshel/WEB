# Task_1 — устройство проекта и правила дальнейшей работы

Описывать и изменять только проект в `Task_1`. Пути ниже указаны относительно этой папки. Перед изменениями сверять описание с текущими исходниками; при изменении связей обновлять этот файл.

## Архитектура и порядок выполнения

Проект использует React 17, ReactDOM 17, Material UI 5, Emotion, PrismJS, Webpack 5, Babel и Express 4. Сервер только раздаёт статические файлы; API, базы данных и серверной фильтрации в проекте нет.

Различать сборку и запуск: Webpack преобразует JSX и импорты в JavaScript-файлы, а Express отдаёт HTML, модели и готовые bundle-файлы браузеру.

| Страница | Модель, загружаемая первой | Точка входа сборки | Компонент | Bundle |
|---|---|---|---|---|
| `getting-started.html` | `modelData/example.js` | `gettingStarted.jsx` | `components/Example/index.jsx` | `compiled/gettingStarted.bundle.js` |
| `p2.html` | `modelData/regions.js` | `p2.jsx` | `components/Regions/index.jsx` | `compiled/p2.bundle.js` |
| `MySearch.html` | `modelData/myData.js` | `mySearch.jsx` | `components/MySearch/MySearch.jsx` | `compiled/mySearch.bundle.js` |

Сначала HTML загружает обычный скрипт модели, который создаёт функцию в `window.lab1models`. После создания `<div id="reactapp">` загружается bundle. Его точка входа вызывает `ReactDOM.render`, компонент читает модель и рисует интерфейс.

Переходы между страницами выполняются обычными ссылками с загрузкой нового HTML. React Router установлен в шаблоне, но кодом приложения не используется.

**КАКИЕ ФУНКЦИИ ВЫПОЛНЯЕТ:** подготавливает страницу компонента Example, кодировку UTF-8, viewport и DOM-контейнер `reactapp`.

**КАКИЕ ИСПОЛЬЗУЕТ МЕТОДЫ БИБЛИОТЕКИ:** напрямую не вызывает методы библиотек; стандартный `<script src>` загружает модель и bundle.

**ЗАВИСИМОСТИ И ВЗАИМОДЕЙСТВИЯ С ДРУГИМИ ФАЙЛАМИ:** загружает `modelData/example.js` до `compiled/gettingStarted.bundle.js`. Bundle создаётся из `gettingStarted.jsx`, который монтирует Example. Общий CSS приходит через импорт в точке входа.

### ФАЙЛ: `gettingStarted.jsx`

**КАКИЕ ФУНКЦИИ ВЫПОЛНЯЕТ:** точка входа React для страницы Example; монтирует один корневой компонент.

**КАКИЕ ИСПОЛЬЗУЕТ МЕТОДЫ БИБЛИОТЕКИ:** `ReactDOM.render(<Example />, ...)` из `react-dom`; стандартный DOM-метод `document.getElementById("reactapp")`. Импорт React нужен для текущего преобразования JSX.

**ЗАВИСИМОСТИ И ВЗАИМОДЕЙСТВИЯ С ДРУГИМИ ФАЙЛАМИ:** импортирует `components/Example/index.jsx` через путь `./components/Example` и `styles/main.css`. Зарегистрирован как `gettingStarted` в `webpack.config.js`; результат загружает `getting-started.html`.

### ФАЙЛ: `components/Example/index.jsx`

**КАКИЕ ФУНКЦИИ ВЫПОЛНЯЕТ:** функциональный компонент Example. Показывает имя из модели, редактируемый девиз, счётчик с шагом раз в две секунды и пример JSX с подсветкой синтаксиса.

**КАКИЕ ИСПОЛЬЗУЕТ МЕТОДЫ БИБЛИОТЕКИ:** React `useState` хранит `name`, `motto`, `counter`; ленивый инициализатор имени читает модель при первом монтировании. `useEffect(..., [])` включает подсветку и запускает таймер. `Prism.highlightAll()` подсвечивает блок `language-jsx`. Стандартные `setInterval` и `clearInterval` запускают и очищают таймер. `setCounter(value => value + 1)` обновляет состояние по предыдущему значению, `setMotto(event.target.value)` обрабатывает ввод.

**ЗАВИСИМОСТИ И ВЗАИМОДЕЙСТВИЯ С ДРУГИМИ ФАЙЛАМИ:** экспортируется по умолчанию и импортируется `gettingStarted.jsx`; вызывает `window.lab1models.exampleModel()` из `modelData/example.js`. Импортирует свой `styles.css`, JSX-грамматику Prism и `prismjs/themes/prism.css`. Общий CSS получает через точку входа. Изменённое имя из файла модели появляется после перезагрузки HTML-страницы: текущий `useState` сам по себе повторно модель не читает.

### ФАЙЛ: `components/Regions/index.jsx`

**КАКИЕ ФУНКЦИИ ВЫПОЛНЯЕТ:** функциональный поиск по семи элементам: шесть областей и Минск. После каждого символа фильтрует данные без учёта регистра, сортирует по русскому алфавиту, показывает запрос и результаты либо сообщение «Совпадений не найдено». Пустой запрос показывает все элементы.

**КАКИЕ ИСПОЛЬЗУЕТ МЕТОДЫ БИБЛИОТЕКИ:** React `useState("")` и setter `setSubstr`; компоненты Material UI `List` и `ListItem`. Стандартные методы JavaScript: `toLocaleLowerCase("ru")`, `includes`, `filter`, `sort`, `localeCompare(..., "ru")`, `map`. `onChange` читает `event.target.value`. `key={name}` задаёт ключ элемента React, `aria-live="polite"` обозначает обновляемые результаты для средств доступности.

**ЗАВИСИМОСТИ И ВЗАИМОДЕЙСТВИЯ С ДРУГИМИ ФАЙЛАМИ:** вызывается из `p2.jsx`; получает массив через `window.lab1models.regionsModel()` из `modelData/regions.js`. Импортирует `styles/main.css` и локальный `styles.css`. Material UI использует установленные Emotion-пакеты. Массив результатов вычисляется при рендере; отдельный `useEffect` для фильтрации не нужен. Сортируется результат `filter`, а не исходная модель.

**ЗАВИСИМОСТИ И ВЗАИМОДЕЙСТВИЯ С ДРУГИМИ ФАЙЛАМИ:** согласован с `package.json`; по нему npm воспроизводит `node_modules`. Хранить в Git, не редактировать вручную. `npm ci` требует согласованности двух файлов, удаляет существующую папку `node_modules` и устанавливает зафиксированные зависимости.

### ФАЙЛ: `.babelrc`

**КАКИЕ ФУНКЦИИ ВЫПОЛНЯЕТ:** конфигурация Babel для преобразования JavaScript и JSX.

**КАКИЕ ИСПОЛЬЗУЕТ МЕТОДЫ БИБЛИОТЕКИ:** задаёт пресеты `@babel/preset-env` и `@babel/preset-react`; прямых вызовов методов нет. Текущий preset-react без настройки автоматического runtime преобразует JSX с использованием React, поэтому сохранять импорт React в JSX-файлах.

**ЗАВИСИМОСТИ И ВЗАИМОДЕЙСТВИЯ С ДРУГИМИ ФАЙЛАМИ:** читается Babel при работе `babel-loader`, заданного в `webpack.config.js`. Зависит от пакетов Babel в `package.json`; распространяется на обрабатываемые `.js`/`.jsx`, кроме `node_modules`.

### ФАЙЛ: `webpack.config.js`

**КАКИЕ ФУНКЦИИ ВЫПОЛНЯЕТ:** определяет три точки входа, обработку исходников, разрешение импортов, имена и папку результатов сборки; работает в режиме `development`.

**КАКИЕ ИСПОЛЬЗУЕТ МЕТОДЫ БИБЛИОТЕКИ:** экспортирует объект конфигурации через CommonJS `module.exports`. Webpack использует `entry`, `module.rules`, `resolve.extensions`, `output`, `mode`; `babel-loader` обрабатывает JS/JSX, `css-loader` затем `style-loader` — CSS, `url-loader` с `limit: 8192` — PNG/JPG/GIF. **ЗАВИСИМОСТИ И ВЗАИМОДЕЙСТВИЯ С ДРУГИМИ ФАЙЛАМИ:** `gettingStarted.jsx`, `p2.jsx`, `mySearch.jsx` собираются в `compiled/[name].bundle.js`. ## Порядок дальнейшей работы

1. Читать этот гайд и затем актуальные исходники затрагиваемых файлов. Не заменять существующую Webpack-структуру другим шаблоном без задачи на такую миграцию.
2. Сохранять функциональные компоненты и контролируемый ввод через `useState`. Для таймеров и подписок использовать `useEffect` с очисткой; производные результаты поиска вычислять при рендере.
3. Сохранять контракт `window.lab1models` и загрузку модели до bundle. При добавлении нового поиска создать модель, компонент, JSX-точку входа и HTML; добавить точку в `webpack.config.js` и ссылку в `index.html`.
4. Для массивов строк сохранять уникальные названия и `key={name}`. При переходе к объектам адаптировать `.filter`, `.sort`, `.map` и ключи. Не изменять исходные массивы сортировкой без копии.
5. Сохранять поиск без учёта регистра, русскую сортировку, мгновенное обновление, показ запроса и сообщение при отсутствии совпадений. Пустая подстрока должна возвращать весь список.
6. Использовать Material UI `List`/`ListItem` для результатов поиска. Не менять совместимость React 17 и Material UI 5 случайным обновлением основных версий. Миграцию на другой ReactDOM API выполнять отдельной согласованной задачей.
7. Коммитить исходники, конфигурацию и `package-lock.json`. Не добавлять `node_modules`, `compiled` и дополнительные материалы. Этот файл относится к документации проекта.
8. После изменений обновлять описание затронутых файлов и запускать подходящие проверки ниже.

## Запуск и проверка

Выполнять из `Task_1`:

```sh
npm ci
npm run build
npm start
```

Открыть `http://localhost:3030/`. Для пересборки при сохранении запускать во втором терминале из той же папки `npm run build:w`; страницу обновлять вручную. Останавливать процессы через Ctrl+C. Команда `npm run dev` в текущем проекте отсутствует.

При изменениях компонентов проверить имя, редактирование девиза и таймер Example; для Regions проверить пустой запрос, `нс`, `НС`, несуществующую подстроку и очистку; для MySearch — `паста`, `ПАСТА`, отсутствие совпадений и очистку. Проверить алфавитный порядок, отсутствие ошибок в консоли и работу на узком экране. Успешная сборка завершается `compiled successfully`, но сама по себе не подтверждает правильность поведения интерфейса.
