# Лабораторная работа № 3

Вариант 10 «Система Ресторан». Исходное условие — приложенный преподавателем файл `Лаб3_JDBC.doc`.

## Часть 1. JDBC API

1. Создать в MySQL таблицы клиентов, меню, заказов, позиций и счетов с внешними ключами.
2. Подключить MySQL Connector/J и читать параметры подключения из `database.properties`.
3. Вынести параметризованные запросы в константы DAO. Создавать заказ с позициями и подтверждать его с выставлением счёта в транзакциях.
4. Проверить меню, историю клиента, список подтверждённых заказов, оформление и оплату.

## Схема базы и 2НФ

| Таблица | Первичный ключ | Данные |
| --- | --- | --- |
| `customers` | `id` | Имя клиента |
| `menu_items` | `id` | Название блюда и текущая цена |
| `restaurant_orders` | `id` | Клиент, время создания и время подтверждения |
| `order_items` | `(order_id, menu_item_id)` | Количество блюда и его цена на момент заказа |
| `invoices` | `order_id` | Время выставления счёта и время оплаты |

У позиции заказа количество и зафиксированная цена зависят от всей пары «заказ, блюдо». Текущая цена и название блюда хранятся в меню. У остальных таблиц ключ состоит из одного столбца. Сумма счёта вычисляется из зафиксированных цен и количества. Подтверждённые заказы видны кухне в пункте 3, включая уже оплаченные.

## Запуск в PowerShell

Нужны JDK 17+, Maven 3.9+ и MySQL 8.4. Для запуска MySQL через Docker Desktop из корня репозитория:

```powershell
cd Task_3
$env:DB_PASSWORD = Read-Host "Пароль для учебного пользователя MySQL"
docker compose up -d
docker compose logs -f mysql
```

После сообщения `MySQL init process done. Ready for start up.` и следующего `ready for connections` нажать Ctrl+C для выхода из просмотра логов. Если база уже запускалась, дождаться `ready for connections` и ввести пароль, заданный при первом запуске. Docker сохраняет данные в томе `restaurant-data`.

Для установленного MySQL создать базу `restaurant`, выдать пользователю права на неё и выполнить `sql/schema.sql`, затем `sql/seed.sql` в этой базе. При необходимости задать `DB_URL` и `DB_USER` в PowerShell. Переменные окружения имеют приоритет над файлом `part1/src/main/resources/database.properties`.

В `Task_3` собрать и открыть первую часть:

```powershell
mvn clean install
mvn -q -pl part1 exec:java
```

Если кириллица вводится или отображается неверно, выполнить `chcp 65001` перед запуском в консоли Windows.

## Проверка сценария

1. Пункты 1 и 7 выводят три блюда и двух клиентов из демонстрационных данных.
2. Пункт 4 для клиента `1` с позициями `1:2 3:1` создаёт заказ на 26.50 BYN. Запомнить выведенный номер.
3. Пункт 2 для клиента `1` показывает заказ со статусом «Новый». Пункт 6 до выставления счёта отклоняет оплату.
4. Пункт 5 подтверждает заказ и выставляет счёт. Пункт 3 показывает заказ и позиции.
5. Пункт 6 регистрирует оплату. Пункт 2 показывает статус «Оплачен». Повторная оплата или подтверждение выводят сообщение.
6. Пункт 4 с позициями `1:2 999:1` отклоняет весь заказ. В истории клиента его нет.

## Часть 2. Пулы соединений

1. Запустить консоль с `MyConnectionPool`. Пул хранит свободные подключения в очереди, выдаёт максимум четыре одновременно и ждёт возврата до трёх секунд, если все заняты.
2. Запустить ту же консоль с классом `DataSource`. Он настраивает и закрывает `HikariDataSource`.
3. Пройти проверочный сценарий для обоих режимов. Проверить параллельную выдачу разных соединений, повторное использование, тайм-аут при заполненном пуле, откат незавершённой транзакции и закрытие пула.
4. При ошибке операции проверить сообщение консоли и запись JUL. HikariCP пишет в этот же журнал через SLF4J.

В том же каталоге `Task_3` после `mvn clean install`:

```powershell
mvn -q -pl part2 exec:java "-Dexec.args=custom"
mvn -q -pl part2 exec:java "-Dexec.args=hikari"
```

Режимы используют одну базу. Каждый запуск продолжает работу с сохранёнными заказами.
